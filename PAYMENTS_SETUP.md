# ЮKassa — запуск LWS Aura

Сайт намеренно не создаёт платежи до 20 февраля 2027 года (00:00, Москва).
Даже после этой даты второй предохранитель `YOO_KASSA_PAYMENTS_ENABLED=true`
должен быть добавлен вручную только после прохождения всех пунктов ниже.

## Что уже подготовлено

- Серверный модуль для создания платежа ЮKassa с Basic Auth и ключом идемпотентности.
- API `POST /api/payments/create`: цена рассчитывается на сервере, а не принимается от браузера.
- Карточные данные остаются на странице оплаты ЮKassa; сайт их не получает.
- Обратный переход после оплаты ведёт на `/checkout`.
- На витрине и в оформлении включён отсчёт до запуска.

## Что заполнить перед включением

В **Vercel → lws-aura → Settings → Environment Variables** нужны только серверные переменные:

```text
YOO_KASSA_SHOP_ID=...
YOO_KASSA_SECRET_KEY=...
YOO_KASSA_PAYMENTS_ENABLED=false
LWS_PRICE_30_RUB=...
LWS_PRICE_50_RUB=...
LWS_PRICE_100_RUB=...
SITE_URL=https://www.auralws.ru
```

`YOO_KASSA_SECRET_KEY` нельзя коммитить, помещать в клиентский код или присылать в чат.
`YOO_KASSA_PAYMENTS_ENABLED` остаётся `false`, пока не будут готовы заказы и чеки.

## Необходимые решения до реального приёма денег

1. Подтвердить магазин ЮKassa именно для LWS Aura либо создать отдельный магазин.
2. Указать цены трёх объёмов в рублях.
3. Настроить в ЮKassa чеки: систему налогообложения, НДС, наименование товара и отправку чеков.
4. Подключить устойчивое хранение заказа и обработчик вебхуков ЮKassa: оплата не должна считаться подтверждённой только после возврата покупателя в браузер.
5. Добавить публичную оферту, правила доставки/возврата и политику обработки персональных данных, затем дать ссылки рядом с согласием в оформлении.

После этого к форме добавляется вызов API и перенаправление на `confirmationUrl`, а вебхук подтверждает оплату в базе заказов.
